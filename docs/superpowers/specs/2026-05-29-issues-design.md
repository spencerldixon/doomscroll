# Issues Design

**Date:** 2026-05-29
**Status:** Approved

## Overview

Add an `Issue` model with user-scoped sequential numbering and a print-ready show page consisting of 24 fixed A4 pages. Content is placeholder layout now; real feed article content wired later.

## Scope

- `Issue` model with `number` auto-assigned per user (1, 2, 3…)
- `issues#show` scoped to current user — other users' issues return 404
- Show page: 24 fixed A4 divs, renders in browser and prints correctly
- Page types: cover, table of contents, 20 article slots, credits, back cover
- No title field — display name is always "Issue #N"

## Out of Scope

- Issue creation UI (issues will be generated by background jobs later)
- Real article content (placeholder text only)
- PDF export / download
- Issue index / list page beyond the existing dashboard cards

## Data Model

### `issues` table

| Column | Type | Notes |
|--------|------|-------|
| `id` | bigint | PK |
| `user_id` | bigint | FK → users, not null |
| `number` | integer | User-scoped sequential, not null |
| `published_at` | datetime | not null |
| `created_at` | datetime | |
| `updated_at` | datetime | |

**Indexes:**
- Unique on `[user_id, number]`
- Index on `user_id`

### Associations

```ruby
# User
has_many :issues, dependent: :destroy

# Issue
belongs_to :user
```

### Sequential number assignment

Inside a transaction, lock the user's issues and assign `MAX(number) + 1`, defaulting to 1 for first issue:

```ruby
def assign_number
  Issue.transaction do
    Issue.where(user: user).lock(true)
    self.number = (Issue.where(user: user).maximum(:number) || 0) + 1
  end
end
```

Called via `before_create :assign_number`. The unique index on `[user_id, number]` is the safety net against race conditions.

## Routes

```ruby
resources :issues, only: [:show]
```

URL: `GET /issues/:id` (AR primary key — `number` is display-only).

## Controller

```ruby
class IssuesController < ApplicationController
  before_action :authenticate_user!

  def show
    @issue = current_user.issues.find(params[:id])
  end
end
```

Scoping to `current_user.issues` means `find` raises `ActiveRecord::RecordNotFound` (→ 404) if the issue belongs to another user or doesn't exist.

## Show Page Layout

### Screen rendering

A full-width scroll container with `background: #888` (grey page gap feel). Each page is a `<section>` with:

```css
width: 210mm;
height: 297mm;
background: white;
margin: 16px auto;
overflow: hidden;
```

### Print CSS

```css
@media print {
  @page { size: A4; margin: 0; }
  body * { visibility: hidden; }
  .issue-pages, .issue-pages * { visibility: visible; }
  .issue-pages { position: absolute; inset: 0; }
  section.page { margin: 0; box-shadow: none; page-break-after: always; }
  nav, header, footer { display: none; }
}
```

### Page structure

| Page | Type | Placeholder content |
|------|------|---------------------|
| 1 | Cover | Zine name (large VT323), "Issue #N", published date, decorative grid background |
| 2 | Table of contents | "Contents" heading, numbered list of 20 article slots ("Article 1" … "Article 20") with mock page numbers |
| 3–22 | Article pages | Each has: article number badge, large headline placeholder, body lorem ipsum (3–4 paragraphs), source label at bottom |
| 23 | Credits | "Published by [zine name]", feed names list, "Generated by Doomscroll" |
| 24 | Back cover | Large issue number (VT323), date, minimal layout |

### Article page architecture

Each article page div carries a `data-page-index` attribute. When real content is added later, an article can span N consecutive page divs without structural change — the controller/presenter will fill `data-page-index` slots accordingly.

```html
<section class="page article-page" data-page-index="0">
  <!-- article slot 1 content -->
</section>
```

## Dashboard Integration

`dashboard/_issue_card.html.erb` already uses `issue.number` and `issue.published_at`. Add link to `issue_path(issue)` on the card (wrapping the cover area or a "Read" button).

The `DashboardController#index` currently sets `@issues = []` — no change needed until issue generation is implemented.

## Error Handling

- `current_user.issues.find(params[:id])` raises `RecordNotFound` → Rails renders 404. No custom message needed (security: don't reveal whether the issue exists for another user).
